KEY PATTERNS & RELATIONSHIPS
============================

Plan → Story (AUTOMATIC)
  Every Plan execution creates a Story

Plan + Supply/Demand → Story + Assembly (TRIGGERED)
  Assembly only created when business logic provides supply/demand

Registry Pattern:
  PlanRegistry.register(name, plan, metadata)
  → Plans stored in Map<string, Plan>
  → Metadata stored in Map<string, PlanMetadata>

Invocation Pattern:
  PlanRegistry.invoke(operation, request, context)
  → Create PlanTransaction { plan, method, params }
  → Execute method on Plan
  → Return StoryResult { success, plan, data, error }

Storage Pattern:
  Story & Assembly stored as versioned ONE objects
  Fields: $type$ = 'Story' or 'Assembly'
  Immutable content-addressed storage via ONE.core
